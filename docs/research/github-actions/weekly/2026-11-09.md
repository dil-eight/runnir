## Current GitHub capabilities and upstream context

- [Actions billing documentation](https://docs.github.com/en/billing/concepts/product-billing/github-actions) distinguishes compute from artifact/cache storage and current inventory from accrued storage. Artifact deletion can reduce current storage and future accumulation without erasing earlier usage. No price, account entitlement, or savings estimate is inferred from the Reddit warning.
- [Artifacts API](https://docs.github.com/en/rest/actions/artifacts) exposes metadata for inventory with Actions read permission. Metadata inspection need not download artifact contents. Deletion is a separate authorized mutation; total account billing cannot be reconstructed reliably from current artifact sizes alone.
- [Checkout v7 release notes](https://github.com/actions/checkout/releases/tag/v7.0.0) document blocking fork PR checkout under workflow_run and pull_request_target. This protection predates the review window; the new finding is user difficulty adapting to it, not a newly introduced release this week.
- [workflow_run documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run) warns about untrusted code obtaining elevated privileges or secrets. A publisher should use trusted code while validating the report as untrusted input, checking originating run/PR identity, and handling output safely. Merely avoiding checkout is insufficient if report processing executes attacker-controlled content.

These documents support inspection and reviewable configuration suggestions. They do not establish an account-specific billing cause, certify a rewritten workflow, or provide an API that repairs runner capacity. No new upstream fix relevant to these included complaints was independently established.

## Feature requests and top three opportunities

The concrete requests are to understand a storage warning, retain safe separation between validation and report publishing, and reduce runner wait without a workflow rewrite. They do not demonstrate demand for automatic artifact deletion, unsafe checkout options, or a Runnir-hosted runner service.

1. **Artifact storage explanation:** show inventory, size, age, and retention with clear separation from compute and accrued billing. Make any cleanup explicit and reviewable.
2. **Workflow trust-boundary preflight:** explain which code and data cross into a privileged workflow_run job; offer a diff using trusted publisher code without weakening checkout protection.
3. **Runner wait visibility:** separate observed queue duration from execution, retain runner labels and freshness, and avoid presenting vendor claims as measured savings.

Roadmap recommendation: preserve P09's focused inspector work; consider P24 as P2 artifact visibility and P10 as P2 explanatory preflight. Keep billing changes, deletion, and workflow mutations behind explicit operator actions. Do not add a new release gate or paid service dependency.
