## Current OIDC capabilities and upstream context

- [GitHub's OIDC reference](https://docs.github.com/en/actions/reference/security/oidc) says id-token: write permits requesting an identity token; it does not grant access to another service. The subject depends on job context and any configured subject template. Repositories using immutable subjects include owner and repository IDs. The source does not establish its repository age, opt-in state, custom template, or emitted subject.
- [Infisical's GitHub OIDC guide](https://infisical.com/docs/documentation/platform/identities/oidc-auth/github) and [general OIDC guide](https://infisical.com/docs/documentation/platform/identities/oidc-auth/general) describe provider-side issuer, subject, audience, claims, and identity-access requirements. GitHub permissions alone cannot validate those external settings.

These are current documentation checks, not a newly shipped upstream fix during this week. No service defect is established. A future preflight may compare explicitly supplied non-secret metadata and explain prerequisites, while showing unknown when provider configuration is unavailable. It should not request or persist raw JWTs, print secret values, widen subject matching, or change policy automatically as part of inspection.
