## Upstream status and current capabilities

- **Stale closure is not resolution:** [act issue 6095's bot comment](https://github.com/nektos/act/issues/6095#issuecomment-7030364334) closed the report on November 20 for inactivity. [PR 6096](https://github.com/nektos/act/pull/6096) remains open and unmerged. E0017 retains its original complaint and P1 classification; no released fix or bundled-version compatibility is claimed.
- **Cache inspection:** [pnpm/setup v3.2.0](https://github.com/pnpm/setup/blob/v3.2.0/README.md) treats save-cache false as restore-only for the package store. [GitHub's caching reference](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching) documents ref isolation and cache-mode limits. [Cache APIs](https://docs.github.com/en/rest/actions/cache) expose key/ref metadata with Actions read access. Inventory alone cannot explain a specific miss; suggestions must check compatible keys and trust boundaries rather than universally enabling writes.
- **Image inspection:** [runner-image guidance](https://github.com/actions/runner-images#latest-migration-process) documents gradual latest-label migrations. A versioned OS label avoids an OS-label migration but still receives image/tool updates. Current Windows image documentation is not proof of the failed run's historical manifest, and does not substantiate a universal Visual Studio transition claimed in answers. [Jobs API](https://docs.github.com/en/rest/actions/workflow-jobs) provides step conclusions; relevant setup logs or a historical manifest are needed for exact versions. Do not suppress compiler compatibility checks as a product recommendation.
- **Corrected product context:** [workflow lockfiles reached GA on October 28](https://github.blog/changelog/2026-10-28-github-actions-workflow-lockfiles-are-generally-available/). The cumulative report now reflects GA, rather than stopping at the earlier preview. Dependency locking does not certify dependency safety.

## Top three opportunities

1. **Explain cache provenance:** show restore/save configuration, an identified compatible producer, and observable key/ref coverage. Mark uninspected keys and cache contents unknown.
2. **Connect matrix failures to execution environment:** show requested runner labels separately from observed image/toolchain versions; offer reviewed guidance without asserting a universal migration or successful fix.
3. **Keep local compatibility checks evidence-based:** distinguish an issue's administrative closure from an implemented fix, and test the actual bundled runner before claiming support. This is a status clarification for the existing P05 opportunity, not new independent demand.
